# 原理与调参指南

这份文档讲**为什么这么写**，以及**界面变了之后怎么改**。只想把它跑起来的话，看 [README](README.md) 就够了。

---

## 1. 判定方式

### 为什么不用「找图案」

最直觉的做法是截一小块目标，然后在屏幕上找它在哪。这个游戏里行不通，原因有两个：

- **这些 UI 内部是大片纯色。** 卷轴中间、按钮中间、卡牌中间都是平涂的奶油色，48×48 的裁切取下来几乎没有任何花纹。拿一块纯色去匹配，屏幕上任何一块空白地方都能给出很高的分数 —— 它永远"找到"自己原来站过的地方。
- **游戏自己绘制鼠标指针。** 鼠标停在目标上时，指针会盖住目标。此时截下来的"模板"里就嵌着一个指针；正式运行时指针早就挪开了，反而再也匹配不上。

所以这里改成比对**整体颜色分布**，不找具体形状。

### 整屏指纹（`type: "screen"`）

把整个屏幕压成 16×9 个格子，每格取平均色，得到一个 9×16×3 的小矩阵，再和参考截图的矩阵逐格求平均绝对差：

```
误差 = mean(|实时指纹 - 参考指纹|)
```

因为这个游戏的 UI 是像素画、位置固定，同一个界面的指纹几乎完全一致，误差通常在 0~12；换成另一个界面，误差会到 40 以上。区分度足够大，不需要复杂的算法。

战场上的小怪会动，会带来几个点的噪声，所以阈值不能卡太死（默认 18）。

### 局部色块（`type: "spot"`）

有些东西只占屏幕一小块，又一直存在，用整屏判定不合适。这时只取一个小矩形的平均色，和参考图里同一个矩形的平均色比较。

因为只比平均色，**不需要精确瞄准**，框偏移几个像素也不影响结果。

### 边沿触发（`edge: true`）

骷髅圆圈是"点一次就消失"的按钮。如果只是"看到就点"，而它又刚好一直停在屏幕上，就会每秒疯狂连点。`edge` 打开后：

1. 命中 → 点击 → **锁定**，不再点
2. 等这一项判定**失败**（按钮消失）→ 解锁
3. 下次再出现 → 可以再点一次

对"点了就消失再出现"的按钮，这是最稳的写法。

## 2. 坐标系

配置里所有坐标都是**屏幕坐标**，单位是物理像素，原点在主显示器左上角。

几个容易踩的坑：

- **DPI 缩放。** 系统缩放 125% / 150% 时，逻辑坐标和物理像素不一致。脚本启动时调用 `SetProcessDpiAwareness(2)` 声明自己按物理像素工作，所以 `--snap` 截出来的图和点击用的是同一套坐标。
- **多显示器。** 截图覆盖整个虚拟桌面，脚本会用 `SM_XVIRTUALSCREEN` 换算原点。但配置里的坐标是按主显示器写的，换显示器之后需要重新量。
- **窗口模式。** 坐标是相对屏幕的，不是相对游戏窗口的。游戏窗口移动或换分辨率后，所有坐标都要重配。

## 3. 怎么量坐标

**第一步，截图。** 停在目标界面，然后：

```bat
python slotbot.py --snap skip
```

3 秒后存成 `shot_skip.png`。（回车后要立刻切回游戏，别用鼠标点窗口。）

**第二步，放大看。** 你想知道「跳过」按钮中心在哪：

```bat
python slotbot.py --cropfile shot_skip.png 1100 880 400 160 3
```

意思是：从 `(1100, 880)` 开始裁 `400×160`，放大 3 倍，存成 `zoom_shot_skip.png`。

放大图和原图是**等比例**的，所以看放大图里的位置就能反推：

```
原图坐标 = 裁剪起点 + (放大图坐标 ÷ 放大倍数)
```

比如放大图里按钮中心在 `(300, 180)`，放大 3 倍，裁剪起点 `(1100, 880)`：

```
x = 1100 + 300 / 3 ≈ 1200
y = 880 + 180 / 3  ≈  940
```

**第三步，验证。** 用 `--snap --mark` 在鼠标位置画准星，确认点没估偏：

```bat
python slotbot.py --snap check --mark
```

## 4. 加一个新界面

假设游戏更新后多了个「商店」界面，你想让它自动点关闭。

1. **截参考图**：停在商店界面，`--snap shop` → 得到 `shot_shop.png`
2. **打开它**，在 `slotbot.json` 的 `states` 里加一项：

```json
{
  "name": "shop",
  "type": "screen",
  "reference": "shot_shop.png",
  "enabled": true,
  "tol": 18,
  "clicks": [[1760, 720]],
  "pick": "first",
  "cooldown": 2.0
}
```

3. **试运行**：`--dry-run --verbose`，看停在商店界面时 `shop=` 的数字是不是很小
4. **调整顺序**：`states` 的数组顺序就是优先级。如果商店界面和别的界面长得像，把它放到前面
5. **正式跑**：确认无误再去掉 `--dry-run`

## 5. 阈值怎么调

`--dry-run --verbose` 每秒打印一行误差：

```
  decision=64.8  skip=62.1  skull=3.2   -> skull ✓
```

读数含义：

| 误差 | 含义 |
| --- | --- |
| 0 ~ 6 | 几乎肯定是这个界面 |
| 6 ~ 15 | 是这个界面，但画面上有动画或其他变化 |
| 15 ~ 30 | 模棱两可，阈值定在这里容易误判 |
| 40 以上 | 肯定不是 |

调参原则：

- **该认得没认出来** → 把这一项的 `tol` 加 2~4
- **不该认的认了** → 把 `tol` 减 2~3，或把 `clicks` 挪到更安全的位置
- 两项误差很接近（比如 12 和 14）→ 说明两个界面太像，整屏判定不够用，考虑用 `spot` 只比区分度最高的那一小块

## 6. 排错清单

| 现象 | 多半是 | 怎么办 |
| --- | --- | --- |
| 启动就退出，说没有可用判定项 | 参考图不在脚本目录 | 确认 `shot_*.png` 和 `slotbot.py` 同级 |
| 所有误差都 40 以上 | 分辨率变了，或控制台挡住了画面 | 用 `--no-minimize` 把窗口挪到角落缩小；或重新截图 |
| 点得偏 | DPI 缩放或窗口位置变了 | 重开游戏后重新量坐标 |
| 同一个按钮连点 | 没开 `edge` | 在那一项加 `"edge": true` |
| 点完鼠标挡住判定区 | `park` 没设 | 在顶层配置里设 `"park": [960, 620]` |
| F8 停不下来 | 游戏全屏独占抢了键盘 | 切到桌面再按 F8，或直接关窗口 |

## 7. 已知限制

- **只认界面，不认内容。** 比如三个卷轴的标题每次都不同，但这里只看"是不是三个卷轴"这个整体形状，所以标题变了照样能认。反过来说，如果游戏在同一个界面里换了配色主题，就得重新截参考图。
- **依赖固定布局。** 换分辨率、改窗口大小、UI 缩放设置变化，都会让坐标准度和指纹一起失效。
- **不适合高帧率实时操作。** 每 0.3 秒判定一次，对回合制、菜单式的操作足够，对需要毫秒级反应的操作不够。
- **只支持 Windows。** 依赖 `user32` 的鼠标接口和 `ImageGrab` 的 GDI 截图。
